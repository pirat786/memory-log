# Архитектура Memory Log

Локальная программа для Windows: в фоне записывает, чем вы занимались за компьютером,
и показывает понятную сводку дня. Данные не покидают компьютер.

## Слои (зависимости идут только сверху вниз)

```
app/            Tauri: окно, трей, команды для интерфейса, сборка в .exe
  ├─ ui/        интерфейс (HTML/CSS/JS без сборки)
  ├─ ml-collector   источники данных (Windows API)      ── реализуют trait Collector
  ├─ ml-storage     SQLite, миграции
  └─ ml-core        чистая логика: модели, категории, сессии, сводка, приватность
```

Правила:
- `ml-core` ничего не знает про ОС, диск и интерфейс. Всё в нём покрыто обычными тестами.
- `ml-collector` только снимает данные и отдаёт `Sample`. Он не пишет в базу.
- `ml-storage` только читает и пишет. Логику сводок не содержит.
- `app` склеивает слои. Бизнес-логики в нём нет.

## Поток данных

1. `collector_loop` раз в 3 секунды вызывает `Collector::sample()` (активное окно),
   раз в 10 секунд `SystemCollector::snapshot()` (процессор, память, сеть, диск, батарея, топ программ).
2. `PrivacyFilter` вырезает чувствительное (банки, пароли) до записи.
3. `Storage` пишет снимки в SQLite (`samples`, `system_samples`, `proc_samples`).
4. Для сводки: выборка за день → `sessionize` (склейка снимков в сессии)
   → `summary::build` (категории, фокус, ритм дня, нагрузка, сеть, цели) → интерфейс.
5. Ошибки записи попадают в `memory-log.log` рядом с базой, а интерфейс показывает
   «Запись идёт» / «Нет новых записей».

## Что собирается и что нет

| Метрика | Источник | Примечание |
|---|---|---|
| Активное окно | WinAPI | заголовки окон, не содержимое |
| Процессор, память, диск | sysinfo | мин/среднее/макс за день |
| Трафик | sysinfo | весь ПК; по программам нужны права администратора (ETW) |
| Батарея | WinAPI | только на ноутбуках |
| Нагрузка по программам | sysinfo | топ-5 по процессору и памяти за снимок, хранится 30 дней |
| Температура | не собирается | Windows без драйверов отдаёт её не на всех ПК |
| Нажатия клавиш | не собирается | счётчик клавиш требует перехвата ввода и похож на кейлоггер |

## Где что менять

| Задача | Где |
|---|---|
| Новые категории и правила | `config/categories.toml` (без правки кода) |
| Что считать приватным | `crates/ml-core/src/privacy.rs` |
| Новый источник данных (буфер обмена, браузер) | новая реализация `Collector` в `ml-collector` |
| Новая таблица / поле | новый файл `crates/ml-storage/migrations/00N_*.sql`, старые не править |

## Заложено на будущее

- **Микрофон и речь.** Таблицы `audio_segments` и `transcripts` уже в схеме (миграция 002).
  План: отдельный крейт `ml-audio` (запись по детектору речи + whisper.cpp локально),
  работает очередью и расшифровывает, когда ПК не загружен. Аудио удаляется через N дней,
  текст остаётся.
- **Шифрование базы.** Заменить `rusqlite/bundled` на `bundled-sqlcipher`, ключ из пароля
  пользователя или Windows DPAPI.
- **Автозапуск, установщик.** Плагин `tauri-plugin-autostart`; установщик NSIS уже в `tauri.conf.json`.
- **Расширение браузера** для точных адресов вкладок (сейчас только заголовки окон).
- **Удаление данных за период.** `Storage::delete_between` уже есть, нужна кнопка в интерфейсе.

## Языки

Все тексты лежат в `ui/i18n/` (по файлу на язык и реестр `languages.json`). Их читают и интерфейс
(`ui/i18n.js`), и Rust (`app/build.rs` встраивает файлы, `app/src/i18n.rs` отдаёт строки для трея,
CSV и ошибок). Язык по умолчанию берётся из Windows, выбранный пользователем хранится в
`language.txt` рядом с базой. Как добавить язык: `ui/i18n/README.md`. Тест следит, чтобы у каждого
языка были те же ключи, что у английского.

## Принципы приватности

- Ничего не отправляется в сеть. В приложении нет сетевых зависимостей.
- Чувствительные окна не попадают в базу вообще.
- Видимый значок в трее и пауза в один клик. Скрытого режима нет.
- Запись разговоров (когда появится) требует отдельного явного включения.
